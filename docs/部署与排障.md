# 部署与排障

> 适用：RDK X5 MagicBox（RDK OS 1.0.0 / Ubuntu 22.04 / TROS Humble）  
> 目标：开机自动运行，孩子说“你好地瓜”即可使用；运行时不依赖终端。

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 硬件 | RDK X5 MagicBox，含双目相机/麦克风/喇叭/灯带；PD 3.0 5V/5A 电源 |
| 系统 | 官方 RDK OS，`/opt/tros/humble/setup.bash` 存在 |
| 官方应用 | `/userdata/magicbox/app/ros_ws/install/setup.bash` 存在，`ros2 pkg prefix audio_io` 有输出 |
| 音频 | `arecord -l` 至少有一张声卡；默认设备 `plughw:0,0` |
| 网络 | 能访问 `api.deepseek.com`（或你自己的 OpenAI-compatible 网关） |
| 密钥 | DeepSeek API key（`DEEPSEEK_API_KEY`） |
| 空间 | 至少 2 GB 空闲用于 SDK 运行时/会话 |
| SDK 版本 | `deepseek-harness-sdk==0.2.1rc2`（安装脚本锁定；升级前先在备用卡上验证） |

> 本项目使用**独立的 DSH_HOME** 和 `sdk-minimal` profile，不复用 DSH Web 端已保存的登录凭据；API key 放在 `/etc/magicbox-tutor.env`。这样儿童设备的会话、工具权限与你的开发用 DSH 完全隔离。

先检查：

```bash
arecord -l
aplay -l
bash -c 'source /opt/tros/humble/setup.bash; source /userdata/magicbox/app/ros_ws/install/setup.bash; ros2 pkg prefix audio_io'
ping -c 3 api.deepseek.com
```

> 如果 `arecord -l` 显示 `no soundcards found`，先不要继续。检查 MagicBox 音频排线/设备树；没有声卡时 `audio_io` 无法启动。

## 2. 安装

把项目目录放到板端（例如 `/home/sunrise/RDK-Dev`），然后：

```bash
cd /home/sunrise/RDK-Dev
sudo ./scripts/install.sh
# 如果桌面用户名不是 sunrise：
# sudo MAGICBOX_TUTOR_USER=你的用户名 ./scripts/install.sh
```

安装脚本会：

1. 检查 TROS、`audio_io`、声卡。
2. 把代码复制到 `/opt/magicbox-tutor`。
3. 创建 `/userdata/magicbox-tutor/{dsh-home,workspace,state}`（权限 700）。
4. 创建 venv（`--system-site-packages`，以便使用 `rclpy`），安装 `deepseek-harness-sdk` 和 PyYAML。
5. 复制配置到 `/etc/magicbox-tutor/config.yaml`、人设到 `/etc/magicbox-tutor/tutor_system_prompt.md`。
6. 创建 `/etc/magicbox-tutor.env` 密钥模板。
7. 停用官方 `magicbox-start`（避免和语音助手抢音频/模型）。
8. 安装并启动 `magicbox-tutor-audio.service` 和 `magicbox-tutor.service`。

如果板端不能联网安装 Python 包，可在有网的电脑下载 wheel，或用 `--skip-deps` 跳过依赖安装（前提是 venv 里已有 `deepseek-harness-sdk` 和 PyYAML）：

```bash
sudo ./scripts/install.sh --skip-deps
```

## 3. 填入密钥并重启

```bash
sudo nano /etc/magicbox-tutor.env
```

写入：

```dotenv
DEEPSEEK_API_KEY=sk-你的密钥
# 如果使用兼容网关：
# DEEPSEEK_BASE_URL=https://your-gateway.example/v1
AUDIO_DEVICE=plughw:0,0
```

保存后：

```bash
sudo chmod 600 /etc/magicbox-tutor.env
sudo systemctl restart magicbox-tutor
```

> 不要把孩子的声音、对话或密钥提交到 git；本项目默认 `log_transcripts: false`。

## 4. 切换千问百炼

如果不想用 DeepSeek，可用阿里云百炼的 Qwen。先确认 key 类型：

| Key 类型 | provider | 环境变量 |
|---|---|---|
| Token Plan 个人订阅（中国站） | `qwen-token-plan-cn` | `QWEN_TOKEN_PLAN_CN_API_KEY` |
| Token Plan 个人订阅（国际站） | `qwen-token-plan-individual` | `QWEN_TOKEN_PLAN_API_KEY` |
| 普通百炼 API Key | `qwen` | `DASHSCOPE_API_KEY` |

安装脚本已附带：

- 示例配置：`/etc/magicbox-tutor/tutor.qwen.yaml`（默认中国站 Token Plan）
- Provider 补丁：`/opt/magicbox-tutor/patches/qwen-bailian.yml`

```bash
sudo cp /etc/magicbox-tutor/tutor.qwen.yaml /etc/magicbox-tutor/config.yaml
sudo nano /etc/magicbox-tutor.env
```

写入（中国站个人订阅）：

```dotenv
QWEN_TOKEN_PLAN_CN_API_KEY=sk-你的TokenPlan个人订阅Key
```

> 用 Token Plan 控制台创建的 **API Key**（`sk-...`），不是阿里云 AccessKey ID/Secret。国际站换成 `QWEN_TOKEN_PLAN_API_KEY`；普通百炼 key 换成 `DASHSCOPE_API_KEY`，并把 `agent.provider` 改成 `qwen`、`agent.api_key_env` 改成 `DASHSCOPE_API_KEY`。

然后：

```bash
sudo systemctl restart magicbox-tutor
journalctl -u magicbox-tutor -n 50 --no-pager | grep -E 'provider=|qwen'
```

应看到 `provider=qwen-token-plan-cn model=qwen3.8-flash`。

> 只改 `DEEPSEEK_BASE_URL` 不行：DSH 默认适配器使用 Anthropic Messages 协议，百炼兼容模式是 OpenAI Chat Completions；必须用 `qwen-bailian.yml` 的 pi-ai 路由。Token Plan 的端点是 `token-plan.cn-beijing.maas.aliyuncs.com`（中国站），如果网络白名单只放了 `dashscope.aliyuncs.com`，需要一并放行。

Token Plan 路由使用 pi-ai 内置模型目录，`qwen3.8-flash` / `qwen3.7-plus` / `qwen3.7-max` 等无需在 patch 里逐条列出；普通 `qwen` 路由在 patch 里列了 `qwen3.8-flash` / `qwen-plus` / `qwen-turbo`，可按账号可用模型增删。切换 provider 后旧 Session 若不能恢复，会自动新建；需要两套独立历史时，给两套配置不同的 `dsh_home`。

## 5. 验证

### 5.1 服务状态

```bash
systemctl status magicbox-tutor-audio --no-pager
systemctl status magicbox-tutor --no-pager
```

两个都应是 `active (running)`。如果 audio 服务反复重启，先看 `arecord -l`。

### 5.2 状态文件

```bash
cat /run/magicbox-tutor/status.json
```

正常会看到类似：

```json
{"state": "idle", "busy": false, "session_id": "session-...", "updated_at": ...}
```

状态文件**不包含对话内容**。

### 5.3 日志

```bash
journalctl -u magicbox-tutor -n 100 --no-pager
journalctl -u magicbox-tutor-audio -n 100 --no-pager
```

看到这些说明链路就绪：

- `DSH 会话已就绪`
- `语音助手已启动: /prompt_text -> /tts_text`
- `TTS -> ...` / `TTS -> end`

### 5.4 语音测试

1. 说“你好地瓜”，听到提示音/看到蓝灯。
2. 问：“三加四等于几？”
3. 应听到短回答。
4. 追问：“那七乘八呢？”应能理解上下文。
5. 说“结束对话”，设备进入呼吸灯；再说“你好地瓜”可重新唤醒。

### 5.5 只测 TTS（可选）

先确保 `audio_io` 在跑，然后：

```bash
source /opt/tros/humble/setup.bash
source /userdata/magicbox/app/ros_ws/install/setup.bash
ros2 topic pub --once /tts_text std_msgs/msg/String "{data: '你好，我是小地瓜老师'}"
ros2 topic pub --once /tts_text std_msgs/msg/String "{data: 'end'}"
```

只发 `"end"` 不会播报；`audio_io` 用它重新开麦。

### 5.6 只测 ASR（可选）

```bash
ros2 topic echo /prompt_text
```

说“你好地瓜”，再说一句话；应看到识别文字。注意 `audio_io` 会过滤掉太短的非中文结果。

## 6. 常用运维

```bash
# 重启
sudo systemctl restart magicbox-tutor

# 停止（保留开机自启）
sudo systemctl stop magicbox-tutor magicbox-tutor-audio

# 临时禁用
sudo systemctl disable --now magicbox-tutor magicbox-tutor-audio

# 恢复官方演示
sudo systemctl disable --now magicbox-tutor magicbox-tutor-audio
sudo systemctl enable --now magicbox-start

# 改人设后
sudo nano /etc/magicbox-tutor/tutor_system_prompt.md
sudo systemctl restart magicbox-tutor

# 改唤醒词/超时/回答长度
sudo nano /etc/magicbox-tutor/config.yaml
sudo systemctl restart magicbox-tutor

# 看最近错误
journalctl -u magicbox-tutor -p err -n 50 --no-pager
```

## 7. 常见问题

### Q1：服务启动但说话没反应

按顺序查：

1. `arecord -l` 有没有声卡。
2. `systemctl status magicbox-tutor-audio` 是否在跑。
3. `journalctl -u magicbox-tutor-audio -n 100` 是否有 ALSA 错误。
4. 说“你好地瓜”时灯变不变蓝；不变蓝说明 KWS/麦克风没工作。
5. 用 5.5 的 TTS 命令测试喇叭。

### Q2：能听到“让我想一想”，但没有答案

说明 ASR 和 TTS 都正常，Agent 没返回。查：

```bash
journalctl -u magicbox-tutor -n 80 --no-pager
```

常见原因：

- `DEEPSEEK_API_KEY` 没填/失效。
- 网络不通，或 `DEEPSEEK_BASE_URL` 写错。
- 模型名不在你的账号/网关里。
- DSH runtime 启动失败（venv/profile/patch/权限）。

### Q3：`DSH 运行时启动失败`

检查：

```bash
ls -la /userdata/magicbox-tutor/dsh-home
ls -la /opt/magicbox-tutor/patches/voice-only.yml
/opt/magicbox-tutor/venv/bin/python -c "import deepseek_harness; print('ok')"
sudo -u sunrise /opt/magicbox-tutor/venv/bin/python -m magicbox_tutor \
  --config /etc/magicbox-tutor/config.yaml --check
```

如果 `--check` 通过但服务失败，看 journal 里的第一条 `DSH 运行时启动失败: ...`。代码现在会打印 SDK 的 stderr 尾部，通常会直接说明原因，例如 `EROFS`、`UNKNOWN_MODEL`、`MISSING_CREDENTIAL`。也可以运行：

```bash
sudo -u sunrise /opt/magicbox-tutor/scripts/doctor.sh
```

常见原因：

- `EROFS`：根文件系统只读，见 Q11。
- `UNKNOWN_MODEL`：`agent.model` 不在 `patches/qwen-bailian.yml` 的 `models` 列表里；加进去或换成已列出的模型。
- `MISSING_CREDENTIAL`：`/etc/magicbox-tutor.env` 没有对应的 key，或 `api_key_env` 名字写错。
- DSH home 权限不是运行用户，或 profile 初始化时无法写目录。

### Q4：TTS 不响，但日志有 `TTS ->`

`audio_io` 只朗读**包含中文**的文本；本项目已经保证每个分句都有中文。仍有问题就看：

- `AUDIO_DEVICE` 是否是 `plughw:0,0`。
- 音量是否被静音：`alsamixer`。
- `audio_io` 是否被 `magicbox-start` 抢了设备。
- 是否发了 `"end"` 导致麦克风状态错乱；重启 audio 服务。

### Q5：唤醒不灵/误唤醒

- KWS 模型是官方 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M`，默认词表是“你好地瓜/地瓜你好/地瓜地瓜/开始对话/结束对话”。
- 安静环境效果最好。本项目不接管实体按键（官方按键逻辑属于已停用的 `magicbox-start`），唤醒入口只有 KWS；若 KWS 不工作，先排查麦克风/模型/噪声。
- 想改“你好小地瓜”需要改 `keywords.txt` 的拼音并验证，不是改配置字符串就行；先用默认词表。

### Q6：回答太长/太短

改 `/etc/magicbox-tutor/config.yaml`：

```yaml
behavior:
  max_answer_chars: 600
  max_sentence_chars: 80
```

再改人设里的“默认 2—4 句，最多 120 字”。两者一起生效。

### Q7：重启后会话变了/没有恢复

默认会从 `/userdata/magicbox-tutor/state/session_id` 读取上次 Session，并调用 DSH 的 `resume_session()`。如果恢复失败，会新建一个，journal 里会有 `恢复会话失败 (...)，将新建会话`。

排查：

```bash
cat /userdata/magicbox-tutor/state/session_id
ls -la /userdata/magicbox-tutor/dsh-home/sessions | tail
journalctl -u magicbox-tutor -n 50 --no-pager | grep -E '恢复|会话'
```

确认 `config.yaml` 里 `agent.resume_session: true`（旧配置没有这个字段时默认就是 true，不必手工添加）。如果换过 DSH 版本、profile、工作目录，或清理过 `dsh-home/sessions`，旧 Session 可能无法恢复，这是预期回退。

### Q8：回答只有一个字/两个字

先看 journal 的 `TTS -> N 字`：如果 N=1，说明**模型只返回了一个字**，不是 TTS 只读一个字。

常见原因：旧会话是 DeepSeek 建的，切换到 Qwen 后仍恢复同一段历史，模型被历史带偏；也可能是人设/模型切换后上下文不兼容。

现在代码会：

- 检查 `session_id.meta.json` 的 provider/model/人设哈希；不一致就不恢复旧会话，自动新建。
- 对较长问题只回 1—2 个字的情况，重置会话并重试一次。
- 旧会话 JSONL 仍保留在 `dsh-home/sessions`，不会删除。

更新代码并重启后，日志应出现 `不恢复旧会话（...），将新建会话`，之后回答恢复正常长度。若仍只有单字，检查 `patches/qwen-bailian.yml` 是否包含当前模型，或运行 `doctor.sh`。

### Q9：孩子说“重新开始”没有反应

检查配置：

```yaml
behavior:
  reset_phrases:
    - 重新开始
    - 新对话
    - 换个话题
```

这句话是 ASR 文字匹配，不需要唤醒词（如果已经在对话中）。如果 `audio_io` 把它当成别的词，换一个更常用的说法。

### Q10：如何清理对话历史

```bash
# 停止服务
sudo systemctl stop magicbox-tutor

# 备份后清理 DSH 会话
sudo mv /userdata/magicbox-tutor/dsh-home/sessions \
        /userdata/magicbox-tutor/dsh-home/sessions.bak.$(date +%s)

# 重新开始
sudo systemctl start magicbox-tutor
```

`dsh-home` 里还有 profile/缓存；不要直接 `rm -rf` 整个目录，除非你要完全重装。

### Q11：重启后所有回答都失败，日志有 `EROFS` / `JsonRpcError`

典型日志：

```text
DSH 运行时启动失败: ... EROFS: read-only file system,
open '/userdata/magicbox-tutor/dsh-home/profiles/sdk-minimal/cordis.yml'
```

这不是 API key 或模型的问题，而是**根文件系统被挂载成了只读**，DSH 无法写 profile/会话。

先确认：

```bash
findmnt -no TARGET,OPTIONS /
# 如果看到 ro,nosuid,nodev... 就是只读
touch /userdata/magicbox-tutor/.probe
```

修复：

```bash
sudo mount -o remount,rw /
findmnt -no TARGET,OPTIONS /
sudo systemctl restart magicbox-tutor
```

也可以用仓库里的脚本（先确认代码已在 `/opt/magicbox-tutor`）：

```bash
sudo /opt/magicbox-tutor/scripts/fix-readonly-root.sh
```

如果 remount 失败：

```bash
sudo dmesg | grep -iE 'ext4|I/O error|read-only|mmcblk' | tail -50
sudo fsck -n /dev/mmcblk1p2     # 只读检查；不要对已挂载可写分区直接 fsck -y
```

`fsck -n` 报错通常意味着 SD 卡文件系统损坏或卡本身不稳定。先备份数据，再从另一台 Linux 或读卡器执行 `sudo fsck -y /dev/mmcblk1p2`；如果反复出现，更换 TF 卡。根文件系统恢复可写后，`/userdata` 和 `/opt/magicbox-tutor` 才能正常写入，会话也才能跨重启保留。

### Q12：如何完全卸载

```bash
sudo ./scripts/uninstall.sh --restore-stock
# 如需删除对话/配置：
sudo ./scripts/uninstall.sh --purge
```

`--purge` 只删除 `/userdata/magicbox-tutor`；`/etc/magicbox-tutor` 和密钥文件默认保留，需手动删。


## 8. 更新代码

```bash
cd /home/sunrise/RDK-Dev
git pull   # 如果你用 git
sudo ./scripts/install.sh
sudo systemctl restart magicbox-tutor
```

安装脚本保留已有 `/etc/magicbox-tutor/config.yaml` 和 `/etc/magicbox-tutor.env`，不会覆盖你的密钥/人设。

## 9. 隐私提醒

- 音频在板端转文字，不上传音频。
- 文字会发给 DeepSeek API；如果使用第三方网关，确认其隐私政策。
- DSH 会话 JSONL 保存在 `/userdata/magicbox-tutor/dsh-home/sessions`，权限 700。
- 安全补丁已禁用 `session-log-deepseek`，不把未接受的会话日志事件上传给模型提供方。
- 默认日志不记录孩子原话；如开启 `log_transcripts: true`，请先征得家长同意并限制 journal 访问。
